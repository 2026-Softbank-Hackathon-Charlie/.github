**전체 규칙(Single Source of Truth): `.claude/skills/finals-constraints/SKILL.md`** — 설계·기능 선택·구현·데모·문서 작업 전에 반드시 읽는다.

## 목표
가동 중인 프로덕션 앱을 하나의 관리 체계로, 멈추지 않고 다른 환경(퍼블릭 A ↔ 퍼블릭 B ↔ 온프렘)으로 옮기고, 실패하면 되돌리며, AI 에이전트는 샌드박스에서 검증한 뒤에만 반영하는 프로덕션 레벨 Multi-cloud Management Platform.
테마: "Beyond Lock-in: Frictionless Cloud Management Across Platforms"

## Hard Constraints (요약)
1. **No Mock**: 어필 기능은 실제 동작. 데모 경로에 하드코딩 값·가짜 진행 바·고정 응답 금지 (fake/stub은 테스트에만).
2. **Live migration**: 이전 중에도 앱이 트래픽을 받고, 에러율·지연을 실시간 표시.
3. **Rollback**: 데이터 동기화 + DNS/트래픽 전환 + 되돌리기. 장애 주입 시 롤백이 실제로 동작.
4. **On-prem 포함**: 퍼블릭 1개 이상 + 자신의 PC/VM. 매니지드 서비스 대체 설계 (S3→MinIO 등).
5. **AI agent = sandbox-then-apply**: 조사 → 샌드박스 시도 → 검증 → 사람 승인 → 반영. 최소 권한, 감사 로그.
6. **Tool-using agent** (Agents SDK, tool calling, MCP). 단순 LLM 호출 X.
7. **플랫폼 품질이 평가 대상**. 앱은 단순하게, 단 프로덕션 특성(DB 상태, 종속 서비스, SLO)은 보이게.
8. **Depth over breadth**: 관점 하나를 프로덕션 레벨까지.
9. **데모 3종 필수**: (a) 가동 중 이전 (b) 멀티 환경 보안·거버넌스 시각화 (c) 에이전트 샌드박스 점검·수정.
10. **슬라이드 없음**: 설계 문서(Notion)로 발표. 트레이드오프·대안·장애 대응을 문서에 기록.
11. **예산 50만 원**, 초과 자비. IaC로 만들고 미사용 리소스는 즉시 destroy.
12. **Secrets 노출 금지** (코드·커밋·로그·문서·데모 화면).

## 작업 규칙
- 새 기능마다 "올리는 심사 항목"과 "기여하는 데모 (a)(b)(c)"를 한 줄로 적는다.
- 데모 경로에 Mock이 필요해 보이면 구현 전에 사람에게 묻는다.
- 클라우드 리소스 코드에는 비용 추정과 정리 방법을 함께 남긴다.
- 설계 결정은 `docs/adr/`에 대안·트레이드오프와 함께 기록. 작은 PR, 의미 있는 커밋 메시지.
